# 13. Le support d'EIP-7702

EIP-7702 permet à un compte externe existant de déléguer son code à un contrat, sans changer d'adresse. `contracts/core/Eip7702Support.sol` relie ce mécanisme à ERC-4337 : un utilisateur peut conserver son adresse historique tout en gagnant le comportement d'un compte de contrat.

Deux constantes portent la reconnaissance. `INITCODE_EIP7702_MARKER` vaut `0x7702` : un `initCode` qui commence par ces deux octets n'est pas une fabrique, mais une autorisation 7702. `EIP7702_PREFIX` vaut `0xef0100` : c'est le préfixe que le protocole place devant l'adresse déléguée dans le code du compte.

Le hachage de l'opération change en conséquence. `_getEip7702InitCodeHashOverride` remplace le hachage de `initCode` par celui de l'adresse déléguée — suivie du reste de `initCode` s'il en reste. C'est le `overrideInitCodeHash` du chapitre 4. La signature couvre ainsi le contrat vers lequel le compte délègue, et non un `initCode` qui ne déploie rien.

Si `initCode` dépasse 20 octets, la charge utile restante est exécutée sur le compte lui-même par `SenderCreator.initEip7702Sender`, pour finaliser l'initialisation. Un échec produit l'erreur `AA13 EIP7702 sender init failed`.

Deux erreurs gardent le cas nominal : `Eip7702SenderWithoutCode` et `Eip7702SenderNotDelegate`.
